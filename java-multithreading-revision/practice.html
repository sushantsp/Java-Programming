    • EX 1 Your First Threads — Hello & World EASY
    Video 3: Creating Threads
    Task: Create a MyThread class extending Thread. In run(), print "World" 5 times in a loop. In main(), print "Hello" 5 times. Start the thread and observe — the output should be interleaved.
    Expected output (random mix — different on every run)
    Hello World Hello Hello World World World Hello World Hello
    Extend Thread, override run() with a loop from 0 to 4 printing "World". In main(): create the object, call start() before the Hello loop, then loop 0 to 4 printing "Hello".
    Ex1.java
    class MyThread extends Thread {
    @Override
    public void run() {
        for (int i = 0; i < 5; i++) System.out.println("World");
    }
}

public class Ex1 {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        t1.start();
        for (int i = 0; i < 5; i++) System.out.println("Hello");
    }
}
    EX 2 The Runnable Way — Plus a Lambda EASY
    Video 3: Creating ThreadsVideo 5: Thread vs Runnable
    Task: Produce the same result as EX 1, but this time implement the Runnable interface. Create the thread via new Thread(runnableObj).start(). Then repeat it once more using a lambda expression: new Thread(() -> {...}).start()
    Expected output
    World Hello World Hello ... (mixed, same interleaving as EX 1)
    Runnable has no start() method — that's why you must wrap the Runnable in a Thread object and pass it to the constructor. Since Runnable is a functional interface, () -> {} works directly as the lambda form.
    Ex2.java
    class World implements Runnable {
    @Override
    public void run() {
        for (int i = 0; i < 5; i++) System.out.println("World");
    }
}

public class Ex2 {
    public static void main(String[] args) {
        World world = new World();
        Thread t1 = new Thread(world);
        t1.start();

        // Bonus — lambda form:
        new Thread(() -> {
            for (int i = 0; i < 5; i++) System.out.println("Lambda");
        }).start();

        for (int i = 0; i < 5; i++) System.out.println("Hello");
    }
}
    EX 3 Lifecycle Observer — A getState() Tour EASY
    Video 4: Thread Lifecycle
    Task: Create a thread whose run() sleeps for 2 seconds. Print its getState() at four points: (1) right after creating the object, (2) immediately after start(), (3) after a 1-second pause in main via Thread.sleep(1000), and (4) after join() returns.
    Expected output
    NEW → RUNNABLE → TIMED_WAITING → TERMINATED
    RUNNING will never appear — it doesn't exist in Java's Thread.State enum (RUNNABLE covers both "ready" and "running"). While a thread is inside sleep(), its state is TIMED_WAITING. After join() returns, the thread has finished, so the state is TERMINATED.
    Ex3.java
    public class Ex3 {
    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new Thread(() -> {
            try { Thread.sleep(2000); } catch (InterruptedException e) { }
        });

        System.out.println("1: " + t1.getState());   // NEW
        t1.start();
        System.out.println("2: " + t1.getState());   // RUNNABLE
        Thread.sleep(1000);                    // t1 is mid-sleep right now
        System.out.println("3: " + t1.getState());   // TIMED_WAITING
        t1.join();                             // wait for it to finish
        System.out.println("4: " + t1.getState());   // TERMINATED
    }
}
    EX 4 Ordering with join() MEDIUM
    Video 6: Essential Methods
    Task: A worker thread performs a 3-second task (sleep(3000), then prints "Work done!"). The main thread must print "Result: task complete" only after the worker finishes. First run it without join() to see the wrong ordering, then add join() to fix it.
    Expected output (with join)
    Main started
    (3 second pause...) Work done!
    Result: task complete
    Call worker.join() before printing the result. join() throws InterruptedException — declare it on main() or wrap in try-catch. Without join(), "Result" prints immediately and "Work done!" arrives 3 seconds later.
    Ex4.java
    public class Ex4 {
    public static void main(String[] args) throws InterruptedException {
        System.out.println("Main started");

        Thread worker = new Thread(() -> {
            try {
                Thread.sleep(3000);            // simulated heavy task
                System.out.println("Work done!");
            } catch (InterruptedException e) { }
        });
        worker.start();
        worker.join();                          // remove this line to see the race

        System.out.println("Result: task complete");
    }
}
    EX 5 Interrupting a Sleeper MEDIUM
    Video 6: Essential Methods
    Task: A worker thread sleeps for 10 seconds. The main thread calls interrupt() after 1 second. In the worker's catch block, print "Interrupted! Slept for: X ms" — measure X using System.currentTimeMillis().
    Expected output
    Interrupted! Slept for: ~1000 ms
    (not 10 seconds — the interrupt woke it early)
    Capture long start = System.currentTimeMillis() right before sleep(). In the catch block, compute elapsed = current − start. In main(), sleep(1000) before calling interrupt() so the worker actually gets to sleep first.
    Ex5.java
    public class Ex5 {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            long start = System.currentTimeMillis();
            try {
                Thread.sleep(10000);           // planned 10s nap
            } catch (InterruptedException e) {
                long slept = System.currentTimeMillis() - start;
                System.out.println("Interrupted! Slept for: " + slept + " ms");
            }
        });
        worker.start();

        Thread.sleep(1000);                    // let it settle into sleep
        worker.interrupt();                    // wake it up
    }
}
    EX 6 Daemon Lifecycle MEDIUM
    Video 6: Essential Methods
    Task: Create a daemon thread that prints "monitoring..." every 200ms in an infinite loop. Create a user thread that does 1 second of work (sleep(1000), then prints "User work done"). Call setDaemon(true) before start(). Observe: the moment the user thread finishes, the JVM kills the daemon.
    Expected output
    monitoring... ×4-5
    User work done
    (program exits — daemon terminated)
    setDaemon(true) must be called before start(), otherwise it throws IllegalThreadStateException. The daemon loop: while(true) { println; sleep(200); } with the InterruptedException handled.
    Ex6.java
    public class Ex6 {
    public static void main(String[] args) {
        Thread monitor = new Thread(() -> {
            while (true) {
                System.out.println("monitoring...");
                try { Thread.sleep(200); } catch (InterruptedException e) { return; }
            }
        });
        monitor.setDaemon(true);           // set BEFORE start
        monitor.start();

        Thread worker = new Thread(() -> {
            try { Thread.sleep(1000); } catch (InterruptedException e) { }
            System.out.println("User work done");
        });
        worker.start();
        // main ends + worker ends → JVM exits → daemon is killed
    }
}
    EX 7 Reproduce and Fix a Race Condition HARD
    Video 7: Synchronization
    Task: Create a Counter class (int field, an increment() method doing count++). Launch 2 threads that each increment 100,000 times — larger numbers make the race easier to observe. Print the final count after both join(). Run it 5–6 times: sometimes you'll get 200000, often less. Then fix it with synchronized — after the fix, it must be 200000 on every run.
    Expected output (without synchronized — different on every run)
    Count: 187342
    Count: 193821
    Count: 200000 (occasionally lucky)

    === after adding synchronized ===
    Count: 200000 (every run)
    Pass the same Counter object to both threads (via constructor or a shared variable). Separate objects won't race — there's nothing shared! The fix: mark the method public synchronized void increment().
    Ex7.java
    class Counter {
    private int count = 0;
    public synchronized void increment() { count++; }  // synchronized = the fix
    public int getCount() { return count; }
}

public class Ex7 {
    public static void main(String[] args) throws InterruptedException {
        Counter counter = new Counter();      // ONE shared object

        Thread t1 = new Thread(() -> {
            for (int i = 0; i < 100000; i++) counter.increment();
        });
        Thread t2 = new Thread(() -> {
            for (int i = 0; i < 100000; i++) counter.increment();
        });

        t1.start(); t2.start();
        t1.join(); t2.join();

        System.out.println("Count: " + counter.getCount());
    }
}
    Experiment deliberately: remove synchronized, run 5–6 times and catch the race in the act. Put it back and confirm stability. This is the reproduce → fix → verify cycle used in real debugging.
    EX 8 Challenge: Rocket Launch Sequence HARD
    Combines everythingVideos 3, 4, 6
    Task: Build a launch controller. Create 3 threads named "Engine-1", "Engine-2", "Engine-3" (custom naming via constructor + super(name)). Each engine counts down 3 → 2 → 1, printing "Engine-X: 3" etc., with a 500ms sleep between numbers. The main thread must join() all engines and only then print "LIFTOFF!". Bonus: assign priorities (one MAX, one MIN) and observe which engine tends to finish first.
    Expected output (interleaved)
    Engine-1: 3 | Engine-2: 3 | Engine-3: 3
    Engine-1: 2 | Engine-3: 2 ...
    (all reach 1, each prints ready)
    LIFTOFF!
    class Engine extends Thread with constructor Engine(String name) { super(name); }. In run(): loop from 3 down to 1, print getName() + count, sleep(500). In main(): create 3 engines, start all, then join all (a for-loop works well), then print LIFTOFF. Without the joins, LIFTOFF prints before the countdowns finish.
    Ex8.java
    class Engine extends Thread {
    public Engine(String name) {
        super(name);                      // Thread constructor — sets the name
    }
    @Override
    public void run() {
        try {
            for (int i = 3; i >= 1; i--) {
                System.out.println(getName() + ": " + i);
                Thread.sleep(500);
            }
            System.out.println(getName() + " ready");
        } catch (InterruptedException e) {
            System.out.println(getName() + " interrupted!");
        }
    }
}

public class Ex8 {
    public static void main(String[] args) throws InterruptedException {
        Engine[] engines = {
            new Engine("Engine-1"),
            new Engine("Engine-2"),
            new Engine("Engine-3")
        };

        // Bonus: priorities (hints, not guarantees)
        engines[0].setPriority(Thread.MAX_PRIORITY);
        engines[1].setPriority(Thread.NORM_PRIORITY);
        engines[2].setPriority(Thread.MIN_PRIORITY);

        for (Engine e : engines) e.start();
        for (Engine e : engines) e.join();   // wait until every engine is ready

        System.out.println("LIFTOFF!");
    }
}
    This exercise combines: extends Thread, custom naming via super(), sleep, join, and priorities. Remove the join loop and watch LIFTOFF print immediately — that's the "JVM waits for user threads" concept in action.
