start() aur run() FROM VIDEO

  • t1.start() — JVM ko batata hai "naya thread banao" — aur us thread mein run() execute hota hai
  • run() — overridden method — jo kaam doosre thread mein karana hai wo yahan likhte hain
  • new Thread() direct banaya toh default run() kuch nahi karta — constructor mein Runnable ya naam dena hota hai
02

sleep() aur join() FROM VIDEO

Thread.sleep(ms)

  • Jo thread is code ko chala raha hai, usko utne milliseconds ke liye pause karta hai
  • InterruptedException throw karta hai — try-catch compulsory

t1.join()

  • Jis thread ne call kiya (caller), wo t1 ke khatam hone ka wait karega
  • Video ka demo: run() mein 5 sec ka sleep tha, main mein join() — Hello 5 second baad print hua, kyunki main ruka tha t1 ke liye
Main.java
// run() mein: Thread.sleep(5000)
public static void main(String[] args) throws InterruptedException {
    MyThread t1 = new MyThread();
    t1.start();
    t1.join();                          // main ruk gaya t1 ke liye
    System.out.println("Hello");   // ye 5 sec BAAD print hoga
}
Output
(5 second wait...)
Hello

join() ke bina Hello turant print hota — main thread rukta nahi. join() lagate hi main t1 ka intezaar karta hai.

Thread Naming FROM VIDEO

  • Default naam: Thread-0, Thread-1, ... (JVM khud deta hai)
  • Custom naam doosre tarike:
    • Apni class mein constructor banao → super(name) call karo (Thread ka constructor)
    • Ya new Thread(runnable, "naam") — Thread ke constructor mein naam pass karo
MyThread.java
class MyThread extends Thread {
    public MyThread(String name) {
        super(name);          // Thread ka constructor — naam set
    }
}
// use:
MyThread t1 = new MyThread("Vipul");
// output mein "Vipul" aayega, "Thread-0" nahi

setPriority() FROM VIDEO

Multiple threads chal rahe hain — CPU kaise decide karega kaun ko zyada time do? Hum khud priority set kar sakte hain:

1
Thread.MIN_PRIORITY
5
Thread.NORM_PRIORITY (default)
10
Thread.MAX_PRIORITY
  • t1.setPriority(Thread.MIN_PRIORITY) — static constants use hote hain
  • Video ka demo: 3 threads (LOW, MEDIUM, HIGH priority) — HIGH wala mostly pehle khatam hua
  • DHYAAN: Ye strict rule NAHI — sirf HINT hai JVM aur OS scheduler ko
  • Actual behavior depend karta hai: code kaisa hai, kitne cores hain, etc.
  • Priority single core pe zyada noticeable hoti hai — multi-core pe toh parallel execution ho sakta hai

Jaise priority video 1 mein padhi thi — high priority ko zyada time slice. Bas wahi cheez yahan hum khud set kar rahe hain.

05

interrupt() FROM VIDEO

  • Meaning: "jo kar rahe ho wahin ruk jao" — agar thread sleep/wait mein hai toh use utha do
  • Agar thread sleep() mein hoga aur interrupt() call hua → InterruptedException throw hota hai
  • Video ka demo: run() mein sleep(1000) tha + try-catch. main() ne t1.interrupt() kiya → sleep interrupted exception aaya, aur sleep ke baad wali line print hi nahi hui
Main.java
// run() mein:
try {
    Thread.sleep(1000);                 // 1 sec sota hai
    System.out.println("Thread is running"); // ye print NAHI hoga
} catch (InterruptedException e) {
    System.out.println("Thread interrupted");
}

// main() mein:
t1.start();
t1.interrupt();  // main ne t1 ko utha diya!
Output
Thread interrupted
java.lang.InterruptedException: sleep interrupted

Interrupt = "Bhai uth jao!" — sote hue thread ko jhataka. Isi liye sleep() interrupted exception throw karta hai.

06

yield() FROM VIDEO

  • Matlab: "main apna CPU use yield karne ko ready hun — doosre threads ko bhi chance do"
  • Official: "A hint to the scheduler that the current thread is willing to yield its current use of a processor. The scheduler is free to ignore this hint."
  • Bilkul priority jaisa — ye bhi sirf HINT hai, guarantee nahi
  • Video ka demo: 2 threads bina yield ke — ek thread apni saari iterations kar leta tha phir doosra. yield() lagane se dono ko alternate chance milne laga (t1, t2, t1, t2...)
run() ke andar
for (int i = 0; i < 5; i++) {
    System.out.println(Thread.currentThread().getName() + " is running");
    Thread.yield();   // har iteration ke baad: doosron ko chance do
}

Pehle: t1 t1 t1 t1 t1 t2 t2 t2 t2 t2 (ek ekata). Yield ke baad: t1 t2 t1 t2 t1 t2... (dono ko chance). Par guarantee nahi — hint hai!

07

User vs Daemon Threads + setDaemon() FROM VIDEO

User Threads

  • Wo threads jo humara actual kaam (business logic) karte hain — jo hum khud create karte hain
  • JVM user threads ka WAIT karta hai — sab user threads khatam hone tak JVM band nahi hota
  • Example: 1 crore baar Hello World print karna hai — JVM wait karega, poora hone dega

Daemon Threads

  • Background threads — jaise Java ka Garbage Collector
  • JVM daemon threads ka WAIT NAHI karta!
  • Agar saare user threads khatam ho gaye → JVM daemon threads ko maar kar band ho jata hai
  • Daemon banane ke liye: t1.setDaemon(true) — start() se PEHLE call karna hota hai

Video ka demo — samajhne wala

Case 1: MyThread daemon banaya (infinite loop, Hello World print karta raha). main() khatam hua → JVM ne daemon ko mar diya. Kuch Hello Worlds print hue, phir sab band.

Case 2: Ek daemon (MyThread) + ek user thread (t1) dono chale. main() khatam → lekin t1 user thread hai, toh JVM t1 ka wait kiya — aur daemon bhi saath chalta raha.

Main.java
MyThread daemon = new MyThread();  // infinite loop mein Hello World
daemon.setDaemon(true);
daemon.start();

// main() ka aakhri statement:
System.out.println("Main done");
// main khatam → user threads koi nahi → JVM band → daemon bhi band!
Output
Hello World
Hello World
Main done
Hello World
(JVM band — daemon terminate ho gaya)

Daemon = "background mein faltu kaam" — JVM bolta hai "user threads khatam? Toh main band, daemon ko maro." User thread zinda hai toh JVM zinda.
