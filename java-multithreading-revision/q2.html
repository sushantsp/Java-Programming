Thread Lifecycle FROM VIDEO

Thread create hoga, chalega, phir terminate hoga — in states ko milakar lifecycle bolte hain.

Video ka analogy: Insaan ka lifecycle — janm hua, 100 saal jiya, phir pata nahi kya hua. Thread ka bhi same:

  • Thread ka execution ke dauraan multiple states aati hain
  • Unhi states ko padhna hai — ye hi hai lifecycle

02

5 States (Theory) FROM VIDEO

Slides mein ye 5 states batayi gayi thi.

StateKab hoti hai
NEWThread ka object create hua hai (jaise new MyThread()) — start() abhi call nahi hua
RUNNABLEt1.start() hote hi — thread ready to run hai, CPU time ka wait kar raha hai. Chala nahi hai abhi!
RUNNINGCPU time mil gaya — thread ab actually execute ho raha hai (run() chal raha hai)
BLOCKED / WAITINGThread kisi cheez ka wait kar raha hai — kisi resource ka access, ya kisi doosre thread ke complete hone ka wait
TERMINATEDThread finish ho gaya — run() ka execution complete

Note: Runnable state wala Runnable interface wala Runnable nahi hai — wo to interface hai. Ye English wala "runnable" hai = able to run.

03

The Twist: Java Enum mein RUNNING nahi hai! FROM VIDEO

getState() internally ek enum return karta hai — aur usme RUNNING naam ki koi value hai hi nahi.

  • Thread.State ek enum hai — states ki fixed values
  • Java enum mein ye values hain: NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED
  • RUNNING exist hi nahi karta!
  • Kyunki Java mein RUNNABLE ka matlab hai: "ya to thread ready-to-run hai, ya actually chal raha hai"
  • Isliye main thread ki state bhi getState() se RUNNABLE aati hai — halanki wo chal hi raha hai

Slides wali RUNNING state sirf samajhne ke liye thi — Java internally usko RUNNABLE mein hi count karta hai.

Live Demo: getState() se har state dekho FROM VIDEO

Video mein MyThread class banake har state print ki thi. Ye raha poora code + timeline.

Code

MyThread.java
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("RUNNING");          // manually print kiya
        try {
            Thread.sleep(2000);                  // t1 2 sec ke liye sleep
        } catch (InterruptedException e) {
            System.out.println(e);
        }
    }
}

public class Main {
    public static void main(String[] args) throws InterruptedException {
        MyThread t1 = new MyThread();
        System.out.println(t1.getState());      // NEW

        t1.start();                              // ab RUNNABLE
        System.out.println(t1.getState());      // RUNNABLE

        Thread.sleep(100);                       // main pause — t1 ko chalne ka mauka
        System.out.println(t1.getState());      // TIMED_WAITING (sleep mein hai)

        t1.join();                               // main t1 ke khatam hone ka wait karega
        System.out.println(t1.getState());      // TERMINATED
    }
}

05

sleep() aur join() FROM VIDEO

Thread.sleep(ms)

  • Jis thread ka code chal raha hai, usko utne milliseconds ke liye pause kar deta hai
  • Ye checked exception throw karta hai — InterruptedException — try-catch ya throws lagana compulsory
  • Thread.sleep(100) main mein = main thread pause hua (kyunki wo main chala raha tha)
  • run() ke andar throws nahi likh sakte — kyunki parent Thread class ka run() throws nahi karta; overridden method checked exceptions add nahi kar sakta — isliye wahan try-catch lagana padta hai

t1.join()

  • Matlab: "jis thread ka code chal raha hai, wo t1 ke finish hone ka wait karega"
  • main() mein t1.join() = main thread wait karega jab tak t1 khatam nahi hota
  • Join ke baad hi next statement chalta hai — isliye join ke baad getState() hamesha TERMINATED deta hai
  • Video mein output thoda late aaya — kyunki main t1 ka wait kar raha tha (2 sec sleep khatam hone tak)

Simple words mein: join() = "t1, kab tak aoge? Main yahin rukta hun."
