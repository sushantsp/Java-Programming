CPU aur Core FROM VIDEO

Sabse basic se — jaise 5th class mein padhte the.

CPU (Central Processing Unit)

  • Brain of the computer — jo bhi program mein likha hai (arithmetic, logic, if-else...), wo CPU ke andar hi run hota hai
  • Jaise tumhari baat samajhne wala tumhara brain hai — waise program samajhne/chalane wala CPU
  • Examples: Intel, AMD

Core

  • Core is an individual processing unit — CPU ke andar actual processing core ke andar hoti hai
  • Pehle CPU mein ek hi core hota tha, ab multiple cores aate hain
  • Quad-core = 4 cores = 4 kaam ek saath (browser, music, document, background kaam)
  • Octa-core = 8 cores (video mein AMD Ryzen 9 ka example diya)
  • Jitne zyada core — utna better

Program, Process, Thread FROM VIDEO

Program

  • Set of instructions — jo kaam karana hai wo instructions likhi hui hain, bas
  • High level pe: Microsoft Word ek program hai, OBS Studio (jisse video record hota hai) ek program hai

Process

  • Process = running instance of a program
  • Program ko jab chalate hain, toh Operating System uski process start kar deta hai
  • Word pe double-click kiya → OS ne Word ki process start kar di

Program = recipe (kagaz pe likha), Process = khana banate waqt wo recipe actually use ho rahi hai.

Thread

  • Thread is the smallest unit of execution within a process
  • Ek process mein multiple threads ho sakte hain — jo kuch resources share karte hain par independently run kar sakte hain
  • MS Word example: ek thread typed words screen pe dikha raha hai, doosra spell-checker chala raha hai (mistake pe underline), teesra auto-save kar raha hai — sab ek saath!
  • Browser example: 5 tabs khule hain toh 5 threads — har tab independent, ek tab doosre pe depend nahi

Multitasking vs Multithreading FROM VIDEO

Ye dono alag cheezein hain — level alag hai.

Multitasking (higher level — processes)

  • OS ki ability — multiple processes simultaneously chalana
  • Example: browser + VLC player (music) + download manager + IDE — sab ek saath
  • Single core pe bhi multitasking hoti thi (purane zamane mein!) — rapid switching se, jaise aadmi do kaam bohot fast switch kare toh lagta hai dono ek saath kar raha hai
  • Multi-core pe — true parallel execution, tasks cores pe distributed hote hain

Multithreading (andar — threads)

  • Ek single process ke andar multiple threads concurrently chalana — yahi multithreading hai
  • Multitasking process level pe hoti hai, multithreading thread level pe (more granular)
  • Multithreading, multitasking ki efficiency enhance karti hai — bade tasks ko chhote sub-tasks (threads) mein todke, CPU ki abilities ka better use

Comparison table

MultitaskingMultithreading
LevelProcesses (OS ka primary unit)Threads (process ka smallest unit)
KahanAlag-alag programs/apps ke beechEk hi application/process ke andar
ResourcesAlag programs — alag memory space ho sakti haiSame process ke threads resources share karte hain
GoalEk saath multiple programs chalanaEk app ke andar multiple tasks — performance + responsiveness

Real-life example (video wala — best remember this!)

Manager + Teams: Manager ke under 4 teams hain, har team pe alag project — ye multitasking hai (4 kaam high level pe ek saath). Ab ek team ke andar dekho — usme kai employees ek hi project pe saath kaam kar rahe hain — wo employees hain threads, aur ye hai multithreading.

Doosra example: video upload karna = ek process. Usme thumbnail banana, editing, description — ye alag tasks/threads. Kaam divide kiya, sab ek saath.

Time Slicing & Context Switching FROM VIDEO

Time Slicing

  • CPU time ko chhote intervals mein divide karna — in intervals ko kehte hain time slices / quantas
  • OS scheduler ye time slices alag-alag processes aur threads ko allocate karta hai
  • Priorities ka bhi khel hai — high priority ko zyada time, low priority ko kam
  • Purpose: ek hi CPU toh hai, bahut saari processes hain — sabko chalne ka mauka mile, koi bhooka na rahe

Jaise apna din plan karna: itne ghante ye kaam, itne ghante wo kaam. CPU ka time bhi aise hi divide hota hai.

Context Switching

  • Process: currently running process/thread ki state save karna, aur next wali ki state load karna
  • Matlab: jo is moment chal raha hai usko pause karo (state save), doosri ko chalao, phir wapas aao usi state se jahan ruka tha
  • Kab hota hai? Jab kisi process/thread ka time slice expire ho jata hai — tab OS scheduler context switch karta hai
  • Purpose: efficiency — cores pe tasks divide karna, sab kuch smooth chalana

Important: pause ki hui cheez shuru se nahi chalegi — jahan ruki thi wahi se resume hogi. Data save hota hai.
